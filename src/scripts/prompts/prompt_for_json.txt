Преобразуй черновые данные в строгий JSON для backend-валидации.

Отвечай только JSON-объектом. Никакого текста до или после JSON.
Не используй Markdown. Не используй ```json.
Не добавляй ключи. Не меняй названия ключей.

Схема ответа:

{
  "content": "",
  "correspondent": "",
  "dateFrom": "",
  "number": "",
  "signedBy": "",
  "recipient": ""
}

Правила нормализации:

1. content
- Значение поля "Содержание".
- Обязательно непустое.
- Одно предложение, максимум 30 слов.

2. correspondent
- Значение поля "Корреспондент".
- Если нет уверенного значения, "".

3. dateFrom
- Только формат ДД.ММ.ГГГГ или "".
- Не преобразуй неоднозначные даты.
- Если дата уже не в формате ДД.ММ.ГГГГ и ее нельзя однозначно привести к этому формату, верни "".

4. number
- Только цифры и дефисы или "".
- Удали "№", "N", "No", "N/", пробелы, буквы и другие символы.

5. signedBy
- Значение поля "Подписано".
- Формат строго "Фамилия И" или "".
- Без точки после инициала.
- Без отчества, должности, телефона, email.

6. recipient
- Значение поля "Имя получателя".
- Формат строго "Фамилия И" или "".
- Без точки после инициала.
- Без отчества, должности, отдела.

Примеры нормализации:
- "15 июня 2026" -> "15.06.2026"
- "№ 123-45/А" -> "123-45"
- "Иванов Андрей Викторович" -> "Иванов А"
- "Иванов А.В." -> "Иванов А"
- "не найдено" -> ""

Если поле отсутствует, сомнительно или противоречиво, ставь "" (кроме поля Содержание).
