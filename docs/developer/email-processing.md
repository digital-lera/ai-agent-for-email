# Обработка почты

Почтовый обработчик реализован в `src/backend/email_check.py`.

## Проверка ящика

`check_email(socketio)`:

1. загружает `src/scripts/login.json`;
2. отправляет текущую статистику в интерфейс;
3. подключается к IMAP;
4. выбирает `INBOX`;
5. ищет `UNSEEN`;
6. вызывает `_process_one_message()` для каждого письма;
7. безопасно завершает IMAP-сессию.

`app.py` вызывает `check_email()` каждые 30 секунд из фоновой задачи Socket.IO.

## Прием письма

`_process_one_message()`:

1. получает исходное письмо через `BODY.PEEK[]`;
2. декодирует `Subject` и `From`;
3. создает `MessageContext`;
4. отправляет события сброса интерфейса и нового письма;
5. загружает правила Directum/email;
6. применяет email-level правила до сохранения вложений;
7. либо останавливается после пересылки, либо входит в обычный PDF pipeline.

Email-level правила могут смотреть на:

- email отправителя;
- полный заголовок отправителя;
- тему и текст письма;
- названия вложений.

Это важно для писем, которые нужно переслать и исключить до OCR, AI и Directum.

## Обработка вложений

`_save_attachments()`:

- отклоняет пустые вложения;
- отклоняет вложения больше `max_attachment_bytes`;
- безопасно нормализует имена файлов через `decode_filename()`;
- добавляет суффикс к повторяющимся именам;
- сохраняет файлы в рабочую папку письма;
- добавляет `.pdf` в `context.pdf_attachments`;
- добавляет текстовые вложения к `context.raw_text`;
- отправляет событие `filename_recognized`.

В OCR попадают только PDF. Другие вложения могут лежать в рабочей папке во
время обработки письма.

## Вход в обычный pipeline

Для обычной обработки нужен минимум один PDF. Если PDF не найден, письмо
помечается для ручной обработки и `run_chain()` не запускается.

Если PDF найден:

1. увеличивается счетчик `received`;
2. запускается `run_chain()`;
3. итог учитывается как `successful`, `partial`, `forwarded_recipient` или
   `manual`.

## Завершение в IMAP

`_move_to_processed()` копирует письмо в `processed_folder`, помечает исходное
письмо как удаленное и выполняет `expunge`. Это происходит только после
успешного маршрута.

`_mark_for_manual_processing()` ставит флаги `\Flagged \Seen`. Этот путь
используется, когда письму нужно ручное внимание или когда не удалось перенести
письмо в папку обработанных.

## Ошибки

Если обработка падает после принятия письма в pipeline:

1. интерфейс получает событие `error`;
2. IMAP-письмо помечается для ручной обработки;
3. `send_error_task.create_error_task()` пытается создать задачу в Directum;
4. счетчик `manual` увеличивается только если задача создана.
