# Саммари проекта

## Назначение

TAIF-mail — сервис для автоматической обработки входящих корпоративных писем.
Он проверяет почтовый ящик, определяет маршрут письма по правилам, извлекает
данные из PDF-вложений, использует AI для структурирования информации и создает
входящие письма или задачи в Directum RX.

## Краткий принцип работы

1. Приложение запускает Flask + Socket.IO интерфейс.
2. Фоновая задача каждые 30 секунд проверяет непрочитанные письма через IMAP.
3. Для каждого письма сначала применяются правила маршрутизации.
4. Если правило требует пересылки и остановки, письмо пересылается по SMTP и не
   идет в AI/Directum.
5. Если письмо идет в обычную обработку, вложения сохраняются во временную
   рабочую папку.
6. Из PDF-вложений извлекается встроенный текст; OCR запускается только для
   сканированных PDF без собственного текста.
7. Текст письма и PDF передаются в локальную модель Ollama.
8. AI возвращает структурированный JSON с данными письма.
9. Приложение ищет связанные сущности в Directum RX.
10. Создается входящее письмо Directum и загружаются вложения.
11. Если часть данных не найдена, создается задача на ручную проверку.
12. После успешного маршрута письмо переносится в IMAP-папку обработанных.

## Используемые технологии

- Python: основной язык backend-логики.
- Flask: HTTP-приложение и отдача веб-интерфейса.
- Flask-SocketIO: realtime-события для статусов обработки и статистики.
- gevent: асинхронная совместимость для Socket.IO.
- IMAP через `imaplib`: получение непрочитанных писем.
- SMTP через `smtplib`: пересылка исходных писем по правилам.
- Python `email`: разбор MIME-писем, заголовков, тела и вложений.
- SQLite: хранение дневной статистики обработки.
- `pdftotext`: извлечение встроенного текста из PDF без OCR.
- EasyOCR: распознавание текста на изображениях страниц PDF, когда встроенного
  текста нет.
- Named volume `easyocr`: кэш detection и recognition моделей EasyOCR между
  перезапусками контейнера.
- pdf2image: конвертация PDF-страниц в изображения для OCR.
- PyTorch + CUDA: GPU-ускорение OCR.
- Ollama: локальный запуск AI-модели.
- Directum RX OData API: создание входящих писем, загрузка вложений и создание
  задач.
- Requests: HTTP-клиент для Directum RX.
- HTML/CSS/SCSS/JavaScript: пользовательский интерфейс.
- unittest: основной набор автоматических тестов.
- Docker / Docker Compose: контейнеризация и развертывание.

## Архитектура

Проект построен как монолитное приложение с четко разделенными слоями:

- `app.py`: точка входа, Flask, Socket.IO и фоновый цикл проверки почты.
- `src/backend/`: бизнес-логика приложения.
- `src/scripts/`: интеграционные и вычислительные модули: Directum, OCR, AI,
  задачи об ошибках и промпты.
- `src/frontend/`: HTML-шаблон, стили и статические ресурсы интерфейса.
- `src/data/`: локальные данные, например SQLite-статистика.
- `tests/`: автоматические тесты.
- `docs/`: документация проекта.

## Основные backend-модули

- `email_check.py`: получает письма, применяет email-level правила, сохраняет
  вложения и управляет IMAP-финализацией.
- `process_message.py`: запускает три этапа pipeline: текст, AI, Directum.
- `directum_rules.py`: загружает и применяет правила маршрутизации.
- `models.py`: описывает общие модели данных и ошибки.
- `statistics.py`: хранит и отправляет дневную статистику.
- `pdf_parse.py`: извлекает текст из PDF.
- `ai_output_json.py`: вызывает Ollama и валидирует JSON.
- `directum.py`: работает с Directum RX OData API и резервным поиском
  контрагента через DaData по ИНН.
- `send_error_task.py`: создает задачу об ошибке в Directum.

## Ключевые маршруты письма

- Письмо исключено правилом отправителя: не идет в AI/Directum.
- Письмо похоже на резюме/CV/отклик: пересылается ответственному сотруднику и
  не идет в AI/Directum.
- Письмо адресовано специальному ID Directum: после распознавания пересылается
  и не создает документ Directum.
- Письмо адресовано одному из получателей с правилом приемной: после поиска
  `recipient_id` пересылается в приемную получателя и не создает документ
  Directum.
- Обычное письмо с PDF: извлекает текст из PDF, при необходимости проходит OCR,
  затем AI и создание входящего письма Directum.
- Обычное письмо с неточными данными: создает документ и задачу на проверку.
- Письмо без PDF: помечается для ручной обработки.
- Ошибка OCR/AI/Directum: письмо помечается вручную, создается задача об ошибке.
