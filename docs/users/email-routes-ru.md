# Маршруты обработки писем

Этот документ описывает, что приложение делает с произвольным входящим письмом.
Он написан для пользователей и операторов, а не для разработчиков.

## Общий принцип

Приложение регулярно проверяет непрочитанные письма во входящем ящике. Для
каждого письма оно определяет маршрут:

- переслать письмо ответственному сотруднику и не обрабатывать дальше;
- отправить письмо в обычную обработку AI и Directum;
- пометить письмо для ручной обработки;
- создать задачу об ошибке в Directum, если автоматическая обработка сорвалась.

После успешного маршрута письмо переносится в папку обработанных писем.


## Маршрут 1. Обычное письмо с PDF

Это основной маршрут для входящих писем.

Что происходит:

1. Приложение получает письмо.
2. Сохраняет вложения во временную рабочую папку.
3. Проверяет наличие PDF.
4. Приложение извлекает текст из PDF. Если PDF является сканом без текста,
   запускается OCR.
5. AI выделяет краткое содержание, контрагента, дату, номер, подписанта и
   адресата.
6. Приложение ищет связанные сущности в Directum.
7. Создает входящее письмо в Directum.
8. Загружает PDF как вложение или версию документа.
9. Считает письмо успешно обработанным.
10. Переносит письмо в папку обработанных.

## Маршрут 2. Обычное письмо, но данные требуют проверки

Иногда документ создается, но часть данных не удалось уверенно сопоставить с
Directum. Например, не найден контрагент, подписант или адресат.

Что происходит:

1. Приложение создает входящее письмо в Directum.
2. Загружает вложения.
3. Создает задачу на проверку данных.
4. В задаче указывает, какие данные требуют ручной проверки.
5. Считает письмо частично обработанным.
6. Переносит письмо в папку обработанных.

## Маршрут 3. В письме нет PDF

Для обычной обработки нужен PDF-файл.

Что происходит:

1. Приложение получает письмо.
2. Сохраняет и проверяет вложения.
3. Не находит PDF.
4. Не запускает OCR.
5. Не запускает AI.
6. Не создает документ в Directum.
7. Помечает письмо флагом для ручной обработки.
8. Не переносит письмо в папку обработанных автоматически.

## Маршрут 4. Ошибка OCR, AI или Directum

Ошибка может возникнуть, если PDF не удалось прочитать, AI вернул некорректные
данные, Directum недоступен или вложение нельзя загрузить.

Что происходит:

1. Приложение останавливает текущую обработку.
2. Показывает ошибку в интерфейсе.
3. Помечает письмо флагом для ручной обработки.
4. Пытается создать задачу об ошибке в Directum.
5. Если задача создана, письмо учитывается как отправленное на ручную
   обработку.
6. Если задача не создана, в интерфейсе появляется дополнительная ошибка.

## Маршрут 5. Замена ID перед созданием документа

Некоторые правила не меняют маршрут письма, а исправляют данные перед созданием
документа в Directum.

Пример: если найден ID `807` (неиспользуемая учетка ТА) у подписанта, адресата или контрагента, он
автоматически заменяется на `582`.

Что происходит:

1. OCR и AI выполняются как обычно.
2. Приложение ищет сущности в Directum.
3. Правило заменяет нужный ID.
4. Документ создается уже с исправленным ID.

## Маршрут 6. Письмо исключено по отправителю

Пример: отправитель `KalmykovaRR@taif.ru` - рассылка меню столовой каждый день

Что происходит:

1. Приложение получает письмо.
2. Проверяет правила обработки.
3. Находит правило исключения по отправителю.
4. Не запускает AI.
5. Не создает документ в Directum.
6. Считает письмо успешно обработанным.
7. Переносит письмо в папку обработанных.

## Маршрут 7. Резюме, CV, кандидат или отклик

Письмо попадает в этот маршрут, если тема или текст письма похожи на одно из
слов:

- `резюме`
- `кандидат`
- `отклик`
- `соискатель`
- `CV`

Также письмо попадает сюда, если имя любого вложенного файла, независимо от
расширения, похоже на:

- `резюме`
- `CV`

Поиск не строго буквальный: для длинных слов допускаются небольшие опечатки.

Что происходит:

1. Приложение получает письмо.
2. Проверяет тему, текст письма и названия вложений.
3. Если найдено совпадение, пересылает исходное письмо на
   `MikhelAA@taif.ru`.
4. Не запускает OCR.
5. Не запускает AI.
6. Не создает документ в Directum.
7. Считает письмо успешно обработанным.
8. Переносит письмо в папку обработанных.

## Что видит пользователь в интерфейсе

В интерфейсе отображаются:

- тема и отправитель нового письма;
- имя найденного вложения;
- этапы обработки: распознавание текста, выделение данных, создание письма в
  Directum;
- выделенные AI данные письма;
- статистика за день;
- ошибка, если обработка сорвалась.

Для писем, которые пересылаются и не идут в AI/Directum, часть этапов может не
запускаться, потому что письмо уже обработано правилом маршрутизации.
